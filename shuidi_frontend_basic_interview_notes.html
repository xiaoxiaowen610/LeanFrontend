1. JavaScript 数组有哪些常用操作方法？
来源：水滴技术面 重要程度：★★★★★ 掌握度：★★★☆☆ 下次复习：建议 Day 1 / 3 / 7
⌄
题目主要考察点和方向概述
1. 能否按用途分类，而不是想到哪说到哪。
2. 是否知道哪些方法会修改原数组。
3. 是否能区分高频相似 API，如 map/forEach、slice/splice、find/filter。
标准答案
数组方法比较多，我一般按用途分类。增删修改类有 push、pop、shift、unshift、splice；遍历转换有 forEach、map、filter；查找判断有 find、findIndex、includes、indexOf、some、every；结构处理有 slice、concat、flat、join，排序有 sort、reverse；聚合类主要是 reduce 和 reduceRight。另外我也会区分哪些方法会修改原数组。
答案整体解析
这题真正要练的是“分类主干”。高级前端不需要机械背完所有 API，但应该能快速组织出：增删修改、遍历转换、查找判断、排序结构、聚合这几类，并补充原数组是否变化。
类别代表方法
增删修改push / pop / shift / unshift / splice
遍历转换forEach / map / filter
查找判断find / findIndex / includes / indexOf / some / every
结构与排序slice / concat / flat / join / sort / reverse
聚合reduce / reduceRight
高频追问 + 答案
追问 1：map 和 forEach 有什么区别？map 会根据回调返回值生成新数组，更适合数据转换；forEach 主要用于遍历执行副作用。
追问 2：slice 和 splice 有什么区别？slice 用于截取，通常不修改原数组；splice 可删除、插入、替换，会修改原数组。
追问 3：find 和 filter 有什么区别？find 返回第一个满足条件的元素；filter 返回所有满足条件元素组成的新数组。
我的失分点
当时主要是零散枚举数组 API，没有形成分类主干，因此容易漏项；最后提到 reduce 后又被继续追问参数，暴露出 API 细节不牢。
记忆钩子
增删 → 遍历 → 查找 → 判断 → 结构 → 聚合。
2. Array.prototype.reduce 有几个参数？
来源：水滴技术面 重要程度：★★★★★ 掌握度：★★☆☆☆ 下次复习：建议明天
⌄
题目主要考察点和方向概述
1. reduce 方法本身的参数数量。
2. callback 的 4 个参数。
3. initialValue 对首次执行和空数组的影响。
标准答案
reduce 方法本身最多接收两个参数：第一个是 reducer 回调函数，第二个是可选的初始值 initialValue。回调函数最多接收四个参数：accumulator、currentValue、currentIndex 和原数组 array。 
array.reduce(callbackFn, initialValue)

callbackFn(accumulator, currentValue, currentIndex, array)
答案整体解析
这题的陷阱是把“reduce 的参数”和“callback 的参数”混在一起。reduce 是 2 个；callback 是 4 个。initialValue 不传时，第一个数组元素会作为初始 accumulator，并从第二项开始执行回调。
高频追问 + 答案
追问 1：不传 initialValue 会怎样？数组第一个元素作为初始 accumulator，从第二个元素开始执行回调。
追问 2：空数组不传 initialValue 呢？会抛出 TypeError。
追问 3：reduce 常见用途？求和、计数、分组、数组转对象、扁平化、串行 Promise 等。
我的失分点
当时回答“2～3 个，具体忘了”，说明 API 签名没有形成条件反射。这类高频基础 API 应该做到秒答。
记忆钩子
reduce 两个，callback 四个。
3. Vue Router 有哪些路由守卫？
来源：水滴技术面 重要程度：★★★★★ 掌握度：★★☆☆☆ 下次复习：建议明天
⌄
题目主要考察点和方向概述
1. 能否按全局 / 路由独享 / 组件内分类。
2. 是否理解 beforeEach、beforeResolve、afterEach 的阶段差异。
3. 是否知道组件内守卫及常见场景。
标准答案
Vue Router 的导航守卫我一般分三类：全局守卫有 beforeEach、beforeResolve、afterEach；路由独享守卫是 beforeEnter；组件内主要有 beforeRouteEnter、beforeRouteUpdate、beforeRouteLeave。Composition API 下还有 onBeforeRouteUpdate 和 onBeforeRouteLeave。
答案整体解析
Route Guard ├─ 全局：beforeEach / beforeResolve / afterEach ├─ 路由独享：beforeEnter └─ 组件内：beforeRouteEnter / beforeRouteUpdate / beforeRouteLeave
回答时先给分类，再列 API。这样比零散报出 beforeEach、afterEach 更完整，也更容易继续承接执行时机和使用场景的追问。
高频追问 + 答案
追问 1：beforeEach 一般做什么？登录鉴权、权限判断、全局重定向。
追问 2：beforeResolve 与 beforeEach 区别？beforeEach 更早；beforeResolve 位于导航确认前较靠后的阶段，适合最终确认类逻辑。
追问 3：afterEach 能阻止导航吗？不能，导航已经完成，适合埋点和页面统计。
追问 4：beforeRouteEnter 为什么访问不到 this？执行时目标组件实例尚未创建。
我的失分点
当时只答了 beforeEach 和 afterEach，没有按三类展开，容易让面试官判断为 Vue Router 基础 API 掌握不完整。
记忆钩子
全局 → 独享 → 组件。
4. Vue3 自定义指令有哪些生命周期？
来源：水滴技术面 重要程度：★★★★☆ 掌握度：★★☆☆☆ 下次复习：建议明天
⌄
题目主要考察点和方向概述
1. 能否按创建 / 挂载 / 更新 / 卸载记忆 7 个钩子。
2. 是否知道 mounted、updated、unmounted 的典型使用场景。
3. 是否了解 Vue2 到 Vue3 的命名变化。
标准答案
Vue3 自定义指令主要有 7 个生命周期钩子：created；挂载阶段的 beforeMount、mounted；更新阶段的 beforeUpdate、updated；卸载阶段的 beforeUnmount、unmounted。
答案整体解析
创建：created 挂载：beforeMount → mounted 更新：beforeUpdate → updated 卸载：beforeUnmount → unmounted
不要死背 7 个名字，按生命周期阶段分组记忆即可。自定义指令本质更偏底层 DOM 行为复用。
高频追问 + 答案
追问 1：mounted 常做什么？DOM 已挂载，适合自动聚焦、事件绑定、第三方 DOM 实例初始化。
追问 2：updated 常做什么？根据新的 binding 值同步更新 DOM 行为。
追问 3：unmounted 常做什么？移除事件监听、清理 timer、Observer 和第三方实例。
我的失分点
生命周期 API 节点不完整，说明 Vue 基础知识存在“用过但没有形成结构化记忆”的问题。
记忆钩子
创建 1 + 挂载 2 + 更新 2 + 卸载 2 = 7。
5. Cookie 和 localStorage 有什么区别？
来源：水滴技术面 重要程度：★★★★★ 掌握度：★★☆☆☆ 下次复习：建议明天
⌄
题目主要考察点和方向概述
1. 是否能从容量、生命周期、网络行为、服务端能力、安全五个维度比较。
2. 是否理解 Cookie 会自动参与 HTTP 请求，而 localStorage 不会。
3. 是否具备 XSS、CSRF、HttpOnly、SameSite 等安全意识。
标准答案
Cookie 和 localStorage 都可以在浏览器保存数据，但区别主要有五点：Cookie 容量较小，通常单条几 KB；localStorage 一般是数 MB。Cookie 可以设置过期时间，localStorage 默认长期保存。Cookie 在满足 Domain、Path、Secure、SameSite 等条件时会随 HTTP 请求自动发送，localStorage 不会。Cookie 可以由服务端通过 Set-Cookie 设置，并支持 HttpOnly、Secure、SameSite；localStorage 主要由前端 JS 操作。因此认证状态常更适合 Cookie，localStorage 更适合非敏感前端状态。
答案整体解析
维度CookielocalStorage
容量通常几 KB / 条通常数 MB
生命周期可设置过期默认长期保存
请求携带满足规则时自动发送不会自动发送
服务端支持 Set-Cookie主要由前端 JS 操作
安全能力HttpOnly / Secure / SameSite可被 JS 直接访问
高频追问 + 答案
追问 1：token 放 Cookie 还是 localStorage？需结合架构与威胁模型。localStorage 遇到 XSS 时 token 可能被读取；HttpOnly Cookie 可阻止 JS 直接读取，但要进一步考虑 CSRF。
追问 2：Cookie 关浏览器就一定没了吗？不一定，设置 Expires 或 Max-Age 后可以持久化。
追问 3：localStorage 真的是永久的吗？准确说是没有内置自动过期机制，默认长期保存，直到用户、浏览器策略或程序主动清理。
我的失分点
当时主要从“存什么数据”回答，没有从存储机制的核心维度比较，且遗漏请求携带和安全属性，这是这题最关键的部分。
记忆钩子
容量 → 生存 → 网络 → 服务端 → 安全。
6. 主域名和子域名如何共享登录态 / 实现免登？
来源：水滴技术面 重要程度：★★★★★ 掌握度：★★☆☆☆ 下次复习：建议明天
⌄
题目主要考察点和方向概述
1. 第一判断应是同根域还是跨根域。
2. 同根域优先考 Cookie Domain，而不是直接跳到 SSO。
3. 跨根域才进入统一认证中心 / SSO / code 或 ticket 交换。
4. 可能继续追问 localStorage 为什么不能直接共享。
标准答案
我会先区分是不是同一个根域。如果是 www.example.com 和 admin.example.com 这种同根域子域，可以通过 Cookie 的 Domain 属性让认证 Cookie 对相应子域生效；如果是 a.com 和 b.com 这种完全不同的根域，Cookie 不能直接共享，一般需要 SSO，通过统一认证中心完成认证，再让各系统建立自己的登录态。
答案整体解析
同根域 www.example.com admin.example.com ↓ Cookie Domain=example.com ↓ 共享认证 Cookie 不同根域 a.com / b.com ↓ 不能直接共享 Cookie ↓ SSO / 统一认证中心 ↓ code / ticket ↓ 各系统建立自己的登录态
高频追问 + 答案
追问 1：父域和子域 localStorage 可以共享吗？不能直接共享。localStorage 按 origin 隔离，协议、Host、端口共同决定 origin，不同子域通常不是同一 origin。
追问 2：为什么 Cookie 可以？Cookie 有独立的 Domain、Path、Secure、SameSite 等作用域规则，可以配置父域对子域生效。
追问 3：什么时候才真正需要 SSO？当系统跨不同根域，或需要统一身份中心、多系统统一登录时，通常采用 SSO。
我的失分点
当时直接回答 SSO，方向不算错，但跳过了“同根域 Cookie Domain”这个更贴近浏览器机制的答案，因此容易被判断为没有答到题眼。
记忆钩子
同根域 → Cookie Domain；不同根域 → SSO；localStorage → 默认不共享。
