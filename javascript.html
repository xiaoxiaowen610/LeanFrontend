#01
JavaScript 有哪些数据类型？基本类型和引用类型有什么区别？
S级 题型：核心原理 刁钻度：★★★★☆ 来源样本：编程猫社招 / 雪球 / 字节
题目主要考察点和方向概述
1. JavaScript 的数据类型完整分类。
2. 基本类型与对象类型在赋值、比较和修改行为上的差异。
3. typeof null、Symbol、BigInt 等常见追问。
标准答案
JavaScript 目前常见的数据类型可以分成两大类。基本类型有 string、number、boolean、undefined、null、symbol、bigint；引用类型本质上都是 Object，包括普通对象、数组、函数、Date、Map、Set 等。

基本类型在赋值时复制的是值，因此修改新变量通常不会影响原变量；对象变量保存的是对对象的引用值，赋值时复制的是这个引用，所以两个变量可能指向同一个对象，对对象内部属性的修改就会互相看到。
答案整体解析
这道题不建议只背“7 种基本类型 + Object”。面试官通常会继续追问 typeof null、对象赋值为什么会联动、Symbol/BigInt 解决什么问题。你要把它当作“JS 类型系统入口题”。
高频追问 + 追问答案
追问 1：typeof null 为什么是 object？
这是 JavaScript 早期实现遗留问题，null 的底层类型标记与对象标记发生了历史上的冲突，因此 typeof null 返回 "object"。判断 null 应直接使用 value === null。
追问 2：函数属于什么类型？
从类型体系看函数属于对象的一种，但 typeof function(){{}} 会返回 "function"，这是 typeof 的特殊结果。
追问 3：对象赋值到底是不是“引用传递”？
更准确地说，JavaScript 参数和变量赋值始终是值传递；对象场景复制的那个“值”恰好是引用值，因此多个变量会指向同一对象。
记忆钩子
7 个基本类型 + Object；对象变量复制的是“引用值”，但 JS 仍然是值传递。
前置知识 / 关联知识
前置：变量、内存基本概念　｜　关联：typeof、instanceof、深浅拷贝、函数参数传递
#02
JavaScript 有哪些类型判断方式？各有什么局限？
S级 题型：核心原理 / 易错 刁钻度：★★★★☆ 来源样本：雪球 / 货拉拉 / 字节
题目主要考察点和方向概述
1. typeof、instanceof、Object.prototype.toString.call、Array.isArray 等常用方式。
2. 每种判断方式的适用范围和缺陷。
3. null、NaN、数组、跨 iframe 等特殊边界。
标准答案
常见类型判断方式有几类：typeof 适合快速判断基本类型和 function，但 typeof null 是 object，普通对象和数组也都会得到 object；instanceof 通过原型链判断对象是否来自某构造函数，适合对象类型，但跨 iframe/realm 时可能失效；Object.prototype.toString.call(value) 能得到类似 [object Array]、[object Date] 的精确标签；数组一般优先使用 Array.isArray；null 用严格等于判断，NaN 推荐 Number.isNaN。
答案整体解析
真正的高分点不是报 API，而是知道“为什么不存在一个万能判断”。不同方式观察的是不同层面：typeof 看语言级标签，instanceof 看原型链，toString.call 看内建类型标签。
高频追问 + 追问答案
追问 1：为什么 instanceof 跨 iframe 可能失败？
因为不同 iframe 拥有不同的全局对象和构造函数，例如两个窗口中的 Array.prototype 并不是同一个对象，所以原型链身份判断可能失败。
追问 2：如何判断数组？
优先使用 Array.isArray(value)，它比 value instanceof Array 更稳妥，尤其跨 realm 场景。
追问 3：如何判断 NaN？
优先 Number.isNaN(value)；全局 isNaN 会先发生类型转换，容易产生误判。
记忆钩子
typeof 看基础标签；instanceof 看原型链；toString.call 做精确类型；数组 Array.isArray。
前置知识 / 关联知识
前置：数据类型　｜　关联：原型链、instanceof、NaN、跨 iframe
#03
Event Loop 是怎么工作的？宏任务和微任务的执行顺序是什么？
S级 题型：核心原理 刁钻度：★★★★☆ 来源样本：编程猫社招 / 美团 / 字节 / 滴滴
题目主要考察点和方向概述
1. 同步调用栈、宿主异步能力和任务队列的协作。
2. 宏任务与微任务的执行顺序。
3. 浏览器渲染时机与常见输出题。
标准答案
浏览器执行 JavaScript 时，当前同步代码先在调用栈中执行。遇到定时器、网络、事件等异步任务，会交给浏览器对应能力处理，完成后把回调放入任务队列。

一次 Event Loop 可以简单理解为：执行一个宏任务 → 执行过程中产生微任务 → 当前宏任务结束后清空微任务队列 → 浏览器在合适时机进行渲染 → 再取下一个宏任务。常见微任务有 Promise.then/catch/finally、queueMicrotask、MutationObserver；常见宏任务有 script、setTimeout、setInterval、I/O、事件回调等。
答案整体解析
面试时不要只说“宏任务之后执行微任务”。核心是：同步栈属于当前任务；每完成一个宏任务，会把当前产生的微任务一直清空，包括微任务中新产生的微任务，再进入下一轮。
高频追问 + 追问答案
追问 1：Promise 构造函数里的代码是同步还是异步？
new Promise(executor) 中 executor 会立即同步执行；异步的是 then/catch 等回调被放入微任务队列。
追问 2：async/await 后半段属于什么？
await 表达式后的继续执行，本质上会以 Promise continuation 的形式进入微任务语义。
追问 3：requestAnimationFrame 在哪里？
它不是普通宏任务 API。浏览器通常在下一次绘制前执行 rAF 回调，因此讨论顺序时要结合渲染机会，而不能简单塞进 setTimeout 那套任务分类。
记忆钩子
一个宏任务 → 清空所有微任务 → 可能渲染 → 下一个宏任务。
前置知识 / 关联知识
前置：调用栈、Promise　｜　关联：async/await、浏览器渲染、长任务、性能优化
#04
什么是闭包？有哪些应用、风险和内存问题？
S级 题型：核心原理 刁钻度：★★★★☆ 来源样本：公开高频 / 社招常见
题目主要考察点和方向概述
1. 闭包的准确含义：函数与其词法环境的组合。
2. 闭包为何能继续访问外层变量。
3. 应用场景与长期引用导致的内存风险。
标准答案
闭包可以理解为函数和它定义时所处词法环境的组合。当一个内部函数引用了外部作用域变量，并且这个内部函数仍然可达时，即使外部函数已经执行结束，相关词法环境仍可能被保留下来，因此内部函数之后仍能访问这些变量。

常见场景有私有状态、函数工厂、缓存、回调、事件处理等。闭包本身不是内存泄漏，但如果闭包长期持有大对象、DOM、定时器相关数据，又没有释放，就可能让这些对象无法被 GC。
答案整体解析
不要把闭包背成“函数嵌套函数”。函数嵌套只是常见表现，关键是内部函数持有外层词法环境中的绑定。高级追问通常会转向作用域、GC、循环闭包和实际项目。
高频追问 + 追问答案
追问 1：闭包一定会导致内存泄漏吗？
不会。只要闭包及其引用的数据最终都不可达，GC 仍会回收。问题在于不必要的长期可达引用。
追问 2：for(var i...) + setTimeout 为什么容易出问题？
var 是函数作用域，多个回调闭包共享同一个 i；循环结束时 i 已经是最终值。使用 let 会让每次迭代创建独立的块级绑定。
追问 3：项目里什么时候会用闭包？
例如封装内部状态、创建带配置的函数、事件/异步回调捕获上下文。但应避免无意捕获巨大对象。
记忆钩子
闭包 = 函数 + 定义时的词法环境；风险不是闭包本身，而是不必要的长期引用。
前置知识 / 关联知识
前置：作用域 / 作用域链　｜　关联：GC、内存泄漏、函数工厂、事件回调
#05
this 的指向规则有哪些？箭头函数为什么特殊？
S级 题型：核心原理 刁钻度：★★★★☆ 来源样本：公开高频
题目主要考察点和方向概述
1. 默认、隐式、显式、new 等 this 绑定规则。
2. 箭头函数没有自己的 this。
3. 绑定优先级和常见 this 丢失问题。
标准答案
普通函数的 this 主要由调用方式决定：普通独立调用属于默认绑定；作为对象方法调用属于隐式绑定；call/apply/bind 属于显式绑定；通过 new 调用时，this 指向新创建的实例。

箭头函数比较特殊，它没有自己的 this，而是词法捕获定义位置外层的 this，因此不能通过 call/apply/bind 改变它自己的 this，也不适合作为构造函数。
答案整体解析
面试重点是“看调用点，不看函数写在哪个对象里”，但箭头函数例外，它看定义位置的外层词法环境。还要知道方法被单独取出来调用时会丢失隐式绑定。
高频追问 + 追问答案
追问 1：const fn = obj.method; fn() 的 this 还是 obj 吗？
不是。方法被取出后调用点不再是 obj.method()，隐式绑定丢失。严格模式下普通函数 this 通常是 undefined。
追问 2：bind 后还能被 new 吗？
可以。对可构造函数使用 bind 后再 new，new 绑定会创建实例，绑定的 thisArg 不会成为最终 this，但预绑定参数仍有效。
追问 3：箭头函数能做对象方法吗？
可以写，但如果方法逻辑依赖“调用对象作为 this”，箭头函数通常不合适，因为它不会建立自己的 this。
记忆钩子
普通函数看调用点；箭头函数看定义位置。
前置知识 / 关联知识
前置：函数调用　｜　关联：call/apply/bind、new、箭头函数、事件回调
#06
Promise 有哪些状态？链式调用、异常穿透、组合 API 怎么理解？
S级 题型：核心原理 刁钻度：★★★★☆ 来源样本：字节 2026 / 雪球 / 好未来
题目主要考察点和方向概述
1. Promise 三状态及不可逆。
2. then/catch 为什么可以链式调用。
3. 返回普通值、Promise、抛异常时链条如何变化。
标准答案
Promise 有 pending、fulfilled、rejected 三种状态，只能从 pending 转到 fulfilled 或 rejected，一旦确定就不会再次变化。

then、catch、finally 都会返回新的 Promise，所以可以链式调用。回调返回普通值时，下一个 Promise 会以这个值 fulfilled；返回另一个 Promise/thenable 时会采用它的最终状态；如果回调抛异常，下一个 Promise 会 rejected。没有提供对应处理函数时，值或错误会继续向后传递。
答案整体解析
这道题建议先把“状态机 + then 返回新 Promise”讲清，再展开 all/race 等组合 API。不要只背 API 结果。
高频追问 + 追问答案
追问 1：Promise executor 同步还是异步？
executor 立即同步执行；resolve 之后注册的 then 回调按微任务执行。
追问 2：finally 会改变链条里的值吗？
通常不会。finally 主要做清理；若 finally 正常完成，原来的值/错误继续传递；如果 finally 自己抛错或返回 rejected Promise，则会覆盖原结果。
追问 3：Promise.all 与 allSettled 区别？
all 任一失败就整体失败；allSettled 会等全部结束，并返回每项 fulfilled/rejected 状态。
记忆钩子
状态一次确定；then 永远返回新 Promise；return 决定值，throw 决定 rejected。
前置知识 / 关联知识
前置：Event Loop　｜　关联：async/await、微任务、组合 API、并发控制
#07
什么是原型、原型对象和原型链？
S级 题型：核心原理 刁钻度：★★★★☆ 来源样本：编程猫社招 / 滴滴 / 雪球
题目主要考察点和方向概述
1. prototype、对象内部 [[Prototype]]、constructor 的关系。
2. 属性查找如何沿原型链向上进行。
3. 继承、instanceof 与原型链的联系。
标准答案
普通函数通常有一个 prototype 属性，这个对象会作为通过该构造函数 new 出来的实例的原型。对象内部有一个 [[Prototype]] 指针，开发中常通过 Object.getPrototypeOf 查看。

访问对象属性时，如果对象自身没有，就沿着 [[Prototype]] 指向的对象继续查找，一层层向上直到找到属性或最终到 null，这条路径就是原型链。JavaScript 的很多继承机制和 instanceof 本质都建立在原型链上。
答案整体解析
最容易混淆的是 Fn.prototype 和 obj.__proto__。前者是函数用于构造实例时提供的原型对象；后者是历史访问器，用来访问对象的内部原型。
高频追问 + 追问答案
追问 1：实例的 __proto__ 和构造函数 prototype 什么关系？
通常 Object.getPrototypeOf(instance) === Constructor.prototype。
追问 2：原型链终点是什么？
普通对象最终通常到 Object.prototype，其内部原型是 null。
追问 3：class 是另一套继承机制吗？
不是。JavaScript class 主要是基于原型继承的语法封装。
记忆钩子
函数 prototype 提供原型；实例 [[Prototype]] 指向它；找属性一路向上就是原型链。
前置知识 / 关联知识
前置：对象 / 函数　｜　关联：new、instanceof、继承、class
#08
深拷贝和浅拷贝有什么区别？如何处理循环引用？
S级 题型：核心原理 刁钻度：★★★★☆ 来源样本：编程猫社招 / 字节
题目主要考察点和方向概述
1. 浅拷贝仅复制第一层，深层对象仍共享引用。
2. 常见浅拷贝、深拷贝方式及能力边界。
3. 循环引用和特殊对象处理。
标准答案
浅拷贝只创建新的第一层容器，第一层属性值会被复制；如果属性值仍是对象，复制的还是原对象引用，所以修改嵌套对象会互相影响。常见浅拷贝有对象展开、Object.assign、数组 slice/concat 等。

深拷贝需要递归或结构化复制整个对象图。现代浏览器可以优先考虑 structuredClone；自定义递归时一般用 WeakMap 记录“原对象 → 新对象”的映射，既能解决循环引用，也能避免重复复制同一引用。还要考虑 Date、RegExp、Map、Set、Symbol、原型、属性描述符等。
答案整体解析
不要把 JSON.parse(JSON.stringify()) 当作标准深拷贝答案，它只是有限场景下的简易方案。高级面试一定会追循环引用和特殊类型。
高频追问 + 追问答案
追问 1：JSON 深拷贝有哪些问题？
会丢失/改变 undefined、函数、Symbol、Date、Map/Set、BigInt、循环引用、原型和属性描述符等。
追问 2：WeakMap 为什么适合处理循环引用？
键是对象且不会阻止对象被 GC；拷贝过程中可以记录已经复制过的对象，遇到同一个源对象时直接复用对应新对象。
追问 3：structuredClone 能拷贝函数吗？
不能。函数等不可结构化克隆的值会导致 DataCloneError。
记忆钩子
浅拷贝复制第一层；深拷贝复制对象图；循环引用用 WeakMap 做映射。
前置知识 / 关联知识
前置：基本/引用类型　｜　关联：Object.assign、structuredClone、WeakMap
#09
Array 有哪些常用方法？怎么分类？哪些会修改原数组？
S级 题型：API完整性 / 刁钻 刁钻度：★★★★★ 来源样本：水滴真题 / 字节 2025 / 雪球
题目主要考察点和方向概述
1. 是否能按用途分类，而不是零散报 API。
2. 是否知道哪些方法会修改原数组。
3. 相似 API 的区别。
标准答案
数组方法我一般按用途分类：增删修改有 push/pop/shift/unshift/splice；遍历转换有 forEach/map/filter；查找判断有 find/findIndex/includes/indexOf/some/every；结构处理有 slice/concat/flat/join；排序和反转有 sort/reverse；聚合有 reduce/reduceRight。

常见会修改原数组的方法包括 push、pop、shift、unshift、splice、sort、reverse、fill、copyWithin；map/filter/slice/concat/find/some/every/reduce 等通常不修改原数组本身。
答案整体解析
这题就是典型“API 完整性题”。面试目标不是背所有 Array API，而是分类清楚，并能处理“是否改原数组”和常见方法对比。
高频追问 + 追问答案
追问 1：map 和 forEach？
map 把每次回调返回值组成新数组；forEach 主要用于遍历执行副作用。
追问 2：slice 和 splice？
slice 截取并返回新数组，通常不改原数组；splice 删除/插入/替换，会原地修改。
追问 3：find 和 filter？
find 返回第一个匹配元素；filter 返回所有匹配元素的新数组。
记忆钩子
增删 / 遍历转换 / 查找判断 / 结构 / 排序 / 聚合。
前置知识 / 关联知识
前置：数组　｜　关联：reduce、sort、forEach+async、不可变数据
#10
Array.prototype.reduce 有几个参数？callback 有几个参数？
S级 题型：API细节 / 刁钻 刁钻度：★★★★★ 来源样本：水滴真题
题目主要考察点和方向概述
1. reduce 方法签名。
2. callback 的 4 个参数。
3. initialValue 对首轮执行和空数组的影响。
标准答案
reduce 方法本身最多接收两个参数：第一个是 reducer 回调函数 callbackFn，第二个是可选的初始值 initialValue。callback 最多接收四个参数：accumulator、currentValue、currentIndex、array。

如果提供 initialValue，第一次执行时 accumulator 就是 initialValue，currentValue 是数组第一个元素；如果不提供，则数组第一个元素作为初始 accumulator，从第二个元素开始执行。空数组且不提供 initialValue 会抛 TypeError。
答案整体解析
水滴这题本质考 API 签名精确度。记忆时一定区分“reduce 两个”和“callback 四个”。
高频追问 + 追问答案
追问 1：空数组传 0 呢？
例如 [].reduce((a,b)=>a+b, 0)，回调不会执行，直接返回初始值 0。
追问 2：reduce 常见场景？
求和、计数、分组、数组转对象、扁平化、Promise 串行等。
追问 3：为什么推荐明确传 initialValue？
结果类型和空数组行为更可预测，也减少首轮特殊情况。
记忆钩子

题目主要考察点和方向概述
1. 三者语义：遍历、副作用、映射、筛选。
2. 返回值差异。
3. 异步回调和提前退出等常见坑。
标准答案
forEach 主要用于遍历并执行副作用，它本身返回 undefined；map 对每个元素做映射，把每次 callback 返回值组成同长度的新数组；filter 根据 callback 的真假筛选元素，返回满足条件的元素组成的新数组。三者都不会因为 callback 中普通 return 而像循环中的 break 一样提前终止整体遍历。
答案整体解析
面试时不要只说“map 有返回值，forEach 没有”。要说清楚它们的语义：forEach 做副作用，map 做转换，filter 做筛选。
高频追问 + 追问答案
追问 1：forEach 可以 break 吗？
不能直接 break。需要提前终止时可以改用 for/for...of、some/every/find 等适合的结构。
追问 2：map 一定不会修改原数组吗？
map 方法本身不修改原数组结构，但 callback 如果主动修改元素对象或原数组，仍然可能产生副作用。
追问 3：filter 返回的元素是深拷贝吗？
不是。新数组容器是新的，但其中对象元素仍可能是原对象引用。
记忆钩子
forEach 做事；map 变形；filter 筛选。

追问 3：sort 现在稳定吗？

追问 1：const 对象为什么还能改属性？

追问 2：全局 var 和 let 有什么区别？
传统浏览器脚本中顶层 var 可能成为全局对象属性；顶层 let/const 不会以同样方式成为 window 属性。
追问 3：TDZ 从什么时候开始？
从进入对应词法作用域开始，到声明语句完成初始化之前。
记忆钩子
var：函数作用域 + 初始化 undefined；let/const：块级作用域 + TDZ。

追问 3：bind 后的函数还能 new 吗？

追问 2：跨 iframe 为什么可能失败？
不同 realm 有不同的 Array 构造函数和 Array.prototype，身份并不相同。
追问 3：instanceof 能判断基本类型吗？
普通基本值通常不行，例如 1 instanceof Number 是 false；new Number(1) instanceof Number 才是 true。

#19
async/await 和 Promise 的关系是什么？连续 await 是串行还是并行？
S级 题型：核心原理 / 易错 刁钻度：★★★★☆ 来源样本：字节 2026 / 雪球
题目主要考察点和方向概述
1. async 函数一定返回 Promise。
2. await 的暂停/恢复语义。
3. 连续 await 导致的串行，以及如何并发。
标准答案
async 函数总会返回一个 Promise：返回普通值会被包装成 fulfilled Promise，抛异常则返回 rejected Promise。await 可以等待 Promise/thenable，也可以等待普通值；当前 async 函数会暂停后续执行，待结果确定后以异步 continuation 继续。

如果写成 const a = await taskA(); const b = await taskB();，taskB 要等 taskA 完成后才开始，因此是串行。若两者无依赖，应先启动：const pa=taskA(); const pb=taskB(); const [a,b]=await Promise.all([pa,pb])。
答案整体解析
高级前端回答时要体现并发意识，而不是只说“async/await 是 Promise 语法糖”。是否串行由“什么时候创建 Promise”决定。
高频追问 + 追问答案
追问 1：await 普通值会怎样？
语义上等价于等待一个已 fulfilled 的 Promise，后续仍通过异步 continuation 继续。
追问 2：如何捕获 await 错误？
可以 try/catch，或者让 async 函数返回 rejected Promise 后由调用方 catch。
追问 3：哪些情况必须连续 await？
后一个任务确实依赖前一个任务结果时，例如先拿 userId 再请求用户详情。
记忆钩子
async 一定返回 Promise；先 await 再启动 = 串行；先启动再 Promise.all = 并发。
前置知识 / 关联知识
前置：Promise、Event Loop　｜　关联：并发请求池、错误处理、性能
#20
防抖和节流有什么区别？边界条件有哪些？
S级 题型：高频 / 手写 刁钻度：★★★★☆ 来源样本：滴滴 / 美团 / 网易
题目主要考察点和方向概述
1. 连续触发时两者不同的执行语义。
2. 典型应用场景。
3. leading/trailing/maxWait/cancel/flush 等工程边界。
标准答案
防抖 debounce 的核心是：事件连续触发时不断重新计时，只有停止触发一段时间后才执行，典型场景是搜索输入、resize 后处理。节流 throttle 的核心是：持续高频触发期间，限制函数最多按某个时间间隔执行一次，典型场景是 scroll、mousemove、持续上报等。

完整实现还要考虑是否首次立即执行 leading、结束后补一次 trailing、最大等待 maxWait、cancel/flush、this/args 透传以及组件卸载清理。
答案整体解析
不要只背“防抖最后一次、节流一段时间一次”。真实场景会追问按钮防重、生成/取消、搜索请求取消等；有些动作不能被简单防抖，否则会吞掉用户操作。
高频追问 + 追问答案
追问 1：搜索框为什么常用防抖？
用户连续输入期间不立即发请求，停止输入一定时间后再执行，可减少无意义请求。
追问 2：滚动监听为什么常用节流？
滚动是持续高频事件，需要周期性获得中间状态，而不是等完全停止后才执行。
追问 3：连续点击“生成/取消”适合直接防抖吗？
不一定。生成和取消是不同业务语义，简单防抖可能吞掉取消动作。更合理的是状态机、AbortController、按钮状态和请求幂等控制。
记忆钩子
防抖等你停；节流持续期间按频率放行；工程版要想 leading/trailing/cancel。
前置知识 / 关联知识
前置：定时器、闭包　｜　关联：搜索、滚动、请求取消、状态机
